# 발행 직후 독자 반응과 결과창

2026-10-11 · D065 / IDEA-RESULT-01 · **아이데이션·충돌 검토 완료, 게임 기능 미구현**.

후속 사용자 D066은 이 문서의 동등한 품질 점수·추가 보너스 후순위 제안을 대체한다: XP는 유지하고 반응은 기사 품질과 독립적으로 무작위, 추가 골드를 지금 도입하며 명시적 재발행에도 허용한다. 아래는 최초 검토 기록이다. 결과 기능 완료 후 D067의 수첩 개편을 이어서 수행한다.

사용자 요구: 먼저 프로젝트 지침에 추가한다. 기사 발행 직후 별도 창이 뜨고 짧은 애니메이션을 거쳐 독자 반응 점수와 경험치·돈의 결과를 보여준다. 카이로소프트의 원리만 참고한다. 먼저 기존 기능과 충돌할 부분을 검토한다.

이번 산출물은 AGENTS.md의 원칙, 아래 결과 흐름·평가/보상 후보·충돌 검토·후속 구현 기준이다. 게임 코드, 의료 본문, 실행 밸런스, 저장 스키마를 변경하거나 커밋·push·배포하지 않는다.

## 참고할 원리와 자체 설계

Kairosoft가 게시한 [Magazine Mogul 소개](https://play.google.com/store/apps/details?id=net.kairosoft.android.magazine_en&hl=en_US)는 기획/관점 선택→현장 취재→출판→독자/지역 성장의 연결을 설명한다(2026-10-11 확인). 이는 ‘내가 만든 결과물이 사람들에게 닿고 성장으로 돌아온다’는 큰 루프의 근거다. 공식 소개만으로 세부 점수 공식·결과창 타이밍을 확인했다고 주장하지 않는다.

이 프로젝트에서는 사용자가 요청한 **발행→짧은 기대감→항목별 숫자 공개→독자 한마디→성장 결과**를 자체 화면과 코드로 만든다. 원작 UI 배치·자산·캐릭터·소리·문구는 복사하지 않는다. 실제 독자에게 배포하거나 실제 반응을 수집하는 온라인 기능은 아니다.

## 첫 결과창의 추천 흐름

| 구간 | 연출 후보 | 플레이어가 받는 정보 |
|---|---|---|
| 발행 직후 | 기존 기사 편집창을 닫고 결과창 하나를 연다. 첫 프레임에 ‘발행 완료’와 보상 요약을 고정 | 발행이 끝났고 결과를 읽는 중임을 즉시 알 수 있음 |
| 약 0~0.5초 | 작은 신문이 접혀 나오고 독자에게 도착하는 짧은 도트 연출 | 내가 쓴 기사가 전달됨 |
| 약 0.5~2초 | 항목별 막대/숫자가 차례로 차오름 | 어떤 부분이 좋았는지와 점수의 이유 |
| 약 2~3초 | 하윤 독자 말풍선과 반응 배지가 등장 | 관찰이 독자의 궁금증을 풀었다는 피드백 |
| 약 3~4초 | XP·골드 숫자와 경험치 게이지, 해당하면 Lv.2 연출 | 이번 발행 +80XP·+100G, 관찰 보상 포함 총 100XP |
| 마무리 | ‘계속 탐험하기’ 또는 ‘기사 다시 읽기’ | 월드나 수첩으로 복귀 |

위 시간은 시안 후보이며 체감 확인 전 확정값이 아니다. ‘결과 바로 보기’로 즉시 마지막 상태를 보여준다. 동작 줄이기 설정에서는 처음부터 최종 결과를 표시한다. 효과음은 기존 원칙대로 음소거 기본이며 시각 결과만으로 모든 정보를 읽을 수 있어야 한다.

화면은 상단의 작은 신문/발행 제목, 가운데 큰 점수와 세 항목, 독자 한마디, 하단 고정 보상/계속 버튼으로 구성한다. 짙은 유리 패널·금색 구분선·청록 반응을 기존 HUD와 맞추고 도트 인물은 기존 합성기를 쓴다. 결과창은 일시적으로 월드를 덮되 상시 HUD나 새 관리 버튼을 추가하지 않는다. 모바일 세로는 한 열, 가로는 연출/점수 두 영역과 고정 하단 버튼으로 검토한다.

## 점수: 먼저 정직하게 평가할 수 있는 것부터

**현재 Q001의 중요한 한계:** 첫 문장 2종은 모두 정확한 범위의 동등한 표현 선택이다. 필수 두 관찰을 맞게 붙이고 편집 확인을 받아야 발행할 수 있으며, 추가 구조 기록은 선택이다. 따라서 현재 저장 상태만으로 발행된 기사들 사이에 의미 있는 품질 차이를 산정할 근거가 없다. 제목 종류·추가 기록 유무·발행 속도만으로 차등 점수를 만드는 것은 피한다.

첫 기사는 ‘첫 취재 완성’ 결과로 시작하는 편이 적합하다. 아래는 **배점 시안**이며 실행용 점수 원본/확정 수치가 아니다.

| 화면 항목 | Q001에서 확인 가능한 것 | 배점 시안 |
|---|---|---:|
| 질문에 답하기 | 돌아오는 길과 폐로 나가는 길을 구분한, 승인된 게임 문장 슬롯을 사용 | 40 |
| 근거 연결 | 직접 얻은 관찰 A/B를 맞는 문단에 연결 | 40 |
| 기사 구성 | 첫 문장·두 본문·맺음말과 출처/한계가 갖춰진 정해진 양식 | 20 |

현재 정상 Q001 발행은 양쪽 표현 모두 100점 후보가 된다. 이는 입문 취재 완성의 게임 피드백이며 ‘의학 정확도 100%’, 실제 독자의 이해도, 기자의 실제 실력 판정이 아니다. 검수 전 상태와 출처/한계는 유지한다. 추가 탐험 메모는 별도 ‘곁들인 이야기’와 독자 한마디를 바꿀 수 있지만 점수/보상/필수 진행을 깎거나 올리는 조건으로 삼지 않는다.

후속 Q002~에서는 **실제로 플레이어가 결정하는 취재 범위·독자별 설명·근거와 주장 연결·한계 설명**이 생긴 뒤 콘텐츠별 이유를 가진 배점을 설계한다. 인기 점수로 부정확한 기사를 발행시키지 않으며, 표현 형태 자체는 우열을 정하지 않는다. 의학적 필수 조건은 발행 전 무료 수정으로 해결한다. 낮은 전달 반응에는 다음에 시도할 구체적인 취재/표현 팁을 준다. 무작위 운·작성 시간·클릭 횟수·옷/집은 평가 입력이 아니다.

## 보상 후보와 경제 경계

**첫 구현 추천:** 점수와 현재 발행 보상을 결과창에서 함께 공개한다. 새로 더 지급하지 않는다. 관찰 20XP는 이미 받은 보상이며 발행은 남은 80XP·100G다. 결과 게이지는 20→100XP, Lv.1→2로 보여준다. 수첩의 다시 보기는 ‘당시 결과 / 이미 받은 보상’으로 표시한다.

점수가 실제 추가 보상도 바꾸게 하려면 다음 단계에서 따로 설계한다. 기존 [경제 설계](../design/05-ECONOMY-AND-NEWSROOM.md)는 기본 기사 보상을 고정하고 P4 이후 선택 품질 보너스를 최대 20%로 제한한다. 이를 앞당기거나 XP를 차등 지급하려면 기존 결정을 명시적으로 바꾸고 Q001~Q010 XP/구매 경로·무구매 진행·저장 호환을 다시 검토해야 한다.

추천 확장은 **필수 XP·기본 골드 고정 + 콘텐츠별로 설명 가능한 제한된 추가 골드**다. 보너스가 없어도 다음 취재와 기존 경제 예산을 충족한다. Q001 고정 보상을 변경하거나 현재 실행 파일에 추가 보너스를 넣는 것은 이번 아이데이션의 수행 범위가 아니다.

## 현재 구현과 충돌할 지점

| 현재 코드/계약 | 그냥 결과창을 추가했을 때의 문제 | 구현 시 해결 조건 |
|---|---|---|
| `domain/article.publishArticle()`이 이미 `grantOnce()`로 80XP·100G를 확정 | 애니메이션 끝에 다시 지급하면 이중 보상, 관찰 20XP까지 발행으로 더하면 Lv.2 예산 초과 | 기존 발행 명령을 확장해 점수·피드백·보상 결과를 한 번 기록. UI는 저장된 결과를 읽기만 함 |

| 기본 보상·Lv.2·초반 경제는 고정 데이터 | 점수에 따라 필수 XP가 줄거나 골드가 폭증해 기존 완주/구매 계획과 충돌 | 첫 표본은 보상 연출만. 점수 연동 보너스는 별도 밸런스 검토 및 원본/파생 문서 동시 갱신 |
| 저장은 로컬 단일 플레이, 실제 독자 계정/구독자 수 상태는 없음 | 가상의 댓글·좋아요·독자 수를 실제 반응 수집처럼 표시 | 게임 속 독자 반응으로 명확히 표현. 라이브 댓글/구독자/수익 서버는 별도 기능 |

이 검토는 현재 소스의 정적 흐름 분석이다. 새 결과 기능을 실행하거나 저장/모바일 회귀 검사를 통과했다는 뜻은 아니다.

## 결과 저장 계약 후보

application에서 발행 때 한 번 계산할 **결과 영수증**은 기사/결과 ID, 평가 규칙 버전, 콘텐츠 판본, 항목 점수와 합계, 이유·독자 반응 ID, 실제 지급한 XP/골드, 발행 당시 XP 전후/레벨, 발행 시각을 포함한다. 결과 확인 시각은 보상과 별도 명령으로 갱신한다.

- 첫 발행: 발행 상태 + 결과 + 보상 장부를 같은 상태로 확정하고 결과창을 연다. 애니메이션 콜백은 상태/보상을 바꾸지 않는다.
- 중간 종료: 저장된 미확인 결과는 다음 실행에서 한 번 다시 열 수 있다. 연출 프레임 자체를 저장할 필요는 없고 최종 결과로 재개해도 된다. 확인 처리 저장이 실패하면 다시 떠도 같은 보상은 추가되지 않는다.
- 다시 보기: 점수/댓글/보상은 당시 영수증 그대로 읽고 지급하지 않는다. 평가 규칙이 업데이트돼도 과거 결과를 덮어쓰지 않는다.
- 기존 발행 저장: 자동으로 새 보상을 주거나 과거에 존재하지 않았던 독자 측정값을 지어내지 않는다. ‘이전 발행 · 반응 점수 기록 없음’과 기존 지급 장부를 보여준다. 새 점수를 계산해 보고 싶다면 실제 당시 결과와 구분한 무보상 미리보기 후보로만 검토한다.

현재 schema4를 그대로 확장할지 schema5로 이행할지는 구현 첫 단계에서 전체 export/import·백업·두 탭 계약과 함께 결정한다. 새 필드를 임의로 넣으면 현재 validator가 보존하지 않으므로 도메인 타입·validator·이행·application 명령을 먼저 변경해야 한다.

## 후속 순서와 완료 기준

1. **RESULT-01**: 결과 영수증/평가 데이터 계약, 발행 원자 처리, 기존 저장 이행. 순수 도메인 테스트로 중복·불변·오버플로·저장 실패·과거 점수 미존재 검증.
2. **RESULT-02**: 결과창·짧은 연출·즉시 결과·동작 줄이기·독자 반응·레벨업. 기사 창에서의 교체/포커스/중단 복귀를 검증.
3. **RESULT-03**: 발행→결과→스킵→재실행→다시 보기, 두 탭·오류·export/import·백업, 모바일 가로/세로·200% 글자·키보드·터치·프레임/리스너 검증. 사용자 체감 확인 후 배포.
4. **RESULT-BALANCE**: 점수 연동 추가 보상이 필요하면 별도 경제 변경으로 검토한다. 첫 세 단계가 보너스 공식의 승인이나 새 예산 완료를 뜻하지 않는다.

현재 완료된 것은 지침 추가와 이 문서의 아이데이션/정적 충돌 검토다. 결과창·점수·애니메이션·보너스는 아직 구현하지 않았다.

# UX-02 뒷모습 팔·모바일 생성 화면

2026-10-11 · D054~D055 · 사용자 지정: 위로 걸을 때 뒷모습 팔과 손을 따로 그리기, 모바일 생성 화면 잘림 수정.

## 변경

- 인물은 `src/art/avatar.ts`에 뒷모습 전용 팔 포즈를 추가했다. 손이 등 중앙으로 들어가지 않으며 가까워지는 손과 멀어지는 손은 크기·높이·색이 다르다. 앞모습의 손바닥 포즈를 공유하지 않는다. 앞·뒤·옆 모두 팔과 다리의 반대 위상, 20×34 캔버스와 발 앵커를 유지한다.
- 생성 카드가 콘텐츠 높이만큼 커지던 세로 화면과 중앙 정렬로 위쪽이 화면 밖에 놓이던 가로 화면을 수정했다. 보이는 화면 높이에 카드가 맞고, 선택 폼은 안쪽에서 스크롤하며 미리보기와 시작/저장·취소 버튼은 남는다.
- 세로는 미리보기/선택/버튼, 가로는 미리보기와 선택 2열이다. 3종 기자 버튼은 세로에서 한 줄이며, 선택 버튼·색 버튼·회전 버튼은 48px 이상이다. 폼 가로 넘침을 막고 큰 글자는 줄바꿈한다.
- 미리보기는 제목·받침대 사이 공간과 폭에 맞춰 정수 device-pixel 배율을 계산한다. visualViewport resize/scroll을 반영하고 편집 종료 시 리스너를 정리한다. 작은 보이는 화면에서는 축소 배치를 쓴다.

## 실제 검증

- 수정 전 브라우저에서 카드 하단 320×568의 y=1654, 390×844의 y=1602, 가로 844×390의 카드 상단 y=-302를 관찰했고 세 가지 경계 검사가 실패했다.
- 수정 후 320×568·390×844·568×320·844×390에서 카드와 전체 미리보기는 화면 안에 있고, 모든 선택 버튼에 스크롤로 접근해 여성/머리 선택 및 시작까지 확인했다. 시작 버튼은 선택 중에도 화면 안에 남는다. 발과 받침대 위치 및 정수 배율도 확인했다.
- 200% 글자+모의 safe-area, 보이는 뷰포트 높이를 320px로 줄였다 복구하는 모의 키보드 조건도 통과했다. 실제 iOS 키보드·사파리·노치 기기를 검사한 결과는 아니다.
- 타입·단위 **79개**·브라우저 **23개**·프로덕션 빌드/콘텐츠 경계 통과. 기존 첫날·Q001·교통·저장·포커스 검사도 포함한다. 생성 화면과 방향별 보행 PNG는 로컬 `artifacts/creator-after-*.png`, `artifacts/walk-cycles.png`로 확인했다.

사용자 미감 승인과 실기기 검증은 남아 있다. 보상·의학 본문·저장 스키마는 이번 작업에서 바꾸지 않았다. 다음 사용자 지정 콘텐츠 범위는 P2 잔여부터 P3까지다.

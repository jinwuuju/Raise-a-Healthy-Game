# 실측 동네 확장 (유로프라자 반경 1km) · 0단계 기록

2026-10-15 · 사용자 확정: 압축 거리 대신 **실제 비율**, **1칸(16px) = 3m**, 유로프라자 일대도 그림은 살리고 위치·거리는 실제 비율로 다시 깐다. 목표는 길·건물 배치가 실제와 90% 이상 비슷한 것(완전 일치 아님). 건물 실제 이름은 사용자가 나중에 넣는다(지금은 형태만). 결정 번호는 다른 작업(실내 D093)과 겹치지 않게 반영 시점에 부여한다.

## 자료와 권리

- **형태(건물 윤곽·도로 중심선·공원/주차장/학교 영역·역):** OpenStreetMap(© OpenStreetMap contributors, ODbL). 원본은 `data/raw/district/osm-1km.json`(Git 제외), 변환은 `tools/district/extract_osm.py`. 게임에 들어가는 파생 지도 데이터는 출처 표기(THIRD_PARTY_NOTICES)와 ODbL 조건을 따른다.
- **눈으로 비교하는 참고 이미지:** Esri World Imagery 항공사진(미리보기에서 OSM 윤곽과 겹쳐 표시), 카카오맵 로드뷰 캡처(`tools/district/roadview.mjs`). 둘 다 `artifacts/map-ref/`(Git 제외)에만 두고 게임 자산·데이터로 복사하지 않는다. 사진 속 상호·로고는 넣지 않는다.
- 층수/높이: OSM에는 반경 300m 건물 523개 중 25개만 있다. 국토부 브이월드 건물통합정보(지상층수, 키 필요) 또는 종류·면적 기반 추정 + 사용자 확인으로 채운다(미정).

## 0단계에서 확인한 사실

| 반경 | 건물 윤곽 | 층수/높이 있음 | 중간 바닥 면적 | 도로·보도 구간 |
|---|---:|---:|---:|---:|
| 300m | 523 | 25 | 150㎡(약 4×4칸) | 134 |
| 600m | 1,909 | 64 | 159㎡ | 389 |
| 1km | 3,671 | 217 | 173㎡ | 1,033 |

1. **유로프라자 주변의 실제 길 관계(OSM 기준, 사용자 확인 필요).** 유로프라자 윤곽(약 41×24m, 논현로 바로 서쪽) 남쪽 정면의 좁은 길은 데이터상 **논현로151길**이며 논현로에서 서남서로 약 28° 기울어 내려간다. 정면 바로 남서쪽에서 **도산대로25길**이 이 길과 엇갈려 남동쪽 도산대로로 내려가고(카페 참고 주소 도산대로25길 19가 이 길), 북쪽으로는 **도산대로27길**이 되어 유로프라자 서쪽 옆을 따라 올라간다. 즉 게임의 ‘앞 골목·건너편으로 내려가는 길·타워 쪽 옆길’ 구조는 실제와 같지만, 게임이 쓰던 이름(앞 골목=논현로159길, 내려가는 길=논현로151길)과 각도는 실제와 다르다. 논현로·도산대로 사거리는 유로프라자에서 남동쪽 약 110m.
2. **격자가 두 갈래.** 1km 안 건물 벽 길이의 약 40%가 도산대로 격자(동쪽에서 약 21° 기울어짐), 유로프라자 주변은 논현로 축(거의 남북)이 27%로 섞인다. 지도를 돌려도(0°, ±21°, -3°) 3m 칸 근사 정확도는 같았다(아래). → **북쪽을 위로 유지**한다(지금 게임·실제 지도와 같은 방향).
3. **3m 칸으로 땅 종류를 근사하면 90%를 못 넘는다.** 1m 정밀 렌더와 비교한 겹침(IoU)은 3m 칸 건물 0.81~0.82·도로 0.79~0.81, 2m 칸 0.85·0.83. 작은 건물과 2~3m 보도가 칸에 뭉개지기 때문이다. → 땅·건물은 **칸에 맞추지 않고 실제 윤곽을 픽셀 단위로(계단식 픽셀 선, 흐림 없음) 미리 그린 청크 이미지**로 표현하고, 이동 충돌은 칸보다 촘촘한 격자로 판정하는 방향을 제안한다. 1칸=3m는 인물·속도·소품의 기준 축척으로 유지한다.

4. **OSM 윤곽과 항공사진은 약 1m 안에서 맞는다.** 반경 300m 건물 윤곽 약 3.7만 점에서 항공사진 경계 세기를 재고 지도 전체를 ±8m 옮겨 보았을 때 가장 잘 맞는 위치가 (0, +1m)였다(`tools/district/align.mjs`). 한 칸(3m)보다 작은 어긋남이다. 단 높은 건물은 사진에서 지붕이 기울어 보여 개별 확인이 필요하다.

## 단계

- 0단계(현재): 자료 추출, 실측 평면도·항공사진 겹침·3m 근사 미리보기, 핵심부 로드뷰 참고 캡처. 게임 코드 변경 없음.
- 1단계: 반경 300m를 실제 비율로 다시 깐다. 청크 렌더·지연 로딩(첫 로딩 JS 예산 유지), 픽셀 윤곽 건물(종류별 외관 템플릿, 사진으로 맞춘 유로프라자·진U·석재·둥근 모서리 건물은 기존 그림), 기존 문(로비·비투비씨) 재배치, 옛 거리 저장 위치 이행, 차량·신호는 큰길·사거리에만. 건물 장부(`id`·윤곽·층수·`name: null`)를 만들어 사용자가 이름을 채운다.
- 2단계: 600m, 3단계: 1km. 단계마다 같은 범위의 항공사진·OSM·게임 렌더 비교 이미지와 자동 검사(도로 중심선 어긋남, 건물 윤곽 겹침) 후 사용자 확인 → 배포.

## 미리보기 만들기

```
python3 tools/district/extract_osm.py                      # data/raw → artifacts/map-ref/district-plan.js
node tools/district/shoot.mjs 이름 'half=150&ppm=5.3333&grid=1&rings=0'   # 게임 축척 핵심부
node tools/district/shoot.mjs 이름 'half=1100&ppm=0.6&sat=1'               # 전체 + 항공사진 겹침
node tools/district/roadview.mjs artifacts/map-ref/roadview/points-core.json
node tools/district/align.mjs 300                        # 윤곽-항공사진 정렬 검사
```

`district-preview.html` 매개변수: `cx,cy` 중심(m), `half` 반폭(m), `ppm` m당 픽셀(게임 축척 16/3), `rot` 회전, `sat=1` 항공사진, `mode=tiles&cell=3` 칸 근사와 겹침 수치, `grid=1` 3m 격자.

## 아직 아닌 것

게임 지도·충돌·저장·배포는 바뀌지 않았다. 도로 폭은 OSM 차로 수 기반 추정이며 항공사진으로 보정 전이다. OSM 윤곽 자체의 오래됨·누락은 사용자 확인으로 찾는다. 사람 눈으로 본 닮음 판정은 사용자 몫이다.

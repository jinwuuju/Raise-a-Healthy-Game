## 실패 원인 진단

1. 이미지 생성기로 만든 “픽셀풍” 고해상도 그림을 정수가 아닌 배율로 줄여 써서 픽셀 크기가 제각각이었다. 인물 시트의 격자도 균일하지 않아 프레임마다 잘리고 흔들렸다.
2. 건물·소품·인물이 서로 다른 해상도와 광원으로 그려져 한 화면에서 따로 놀았다.
3. 실내는 회색 사각형과 임시 그래픽이 섞였고 HUD는 기본 폼 스타일이었다.

## 새 아트 방향 (바람의나라 연을 참고한 자체 스타일)

참고 작품의 캐릭터·타일·UI·지도를 복사하지 않는다. 가져온 것은 “읽히는 원칙”뿐이다.

- 2.3~2.5등신 치비 인물, 큰 눈과 하이라이트, 볼 터치, 1px 어두운 보라 윤곽선. 24×33 캔버스, 발 앵커 고정, 4방향 × (정지·왼발·오른발) 3프레임.
- 위에서 비스듬히 내려다보는 2.5D: 건물은 지붕(평면) + 정면 벽으로 그리고, 발 y 기준으로 앞뒤를 정렬한다. 건물/나무 뒤로 들어가면 인물 실루엣이 반투명으로 보인다.
- 따뜻하고 채도 있는 팔레트, 좌상단 광원, 오른쪽 아래 그림자. 10월 서울에 맞춰 노랗게 물드는 은행나무와 떨어지는 잎.
- 머리 위 이름표·퀘스트 느낌표·장소 배너·둥근 행동 버튼처럼 모바일 RPG에 익숙한 정보 표현. 단 HUD 원칙에 따라 월드 화면을 덮지 않는다.

## 기술 결정

- 모든 그래픽은 코드로 한 픽셀씩 그린다(외부 이미지 0장). 타일 16px, 화면은 정수 배율로만 확대하고 이름표·UI 글자는 화면 해상도로 따로 그려 선명하게 유지한다.
- Phaser를 제거하고 Canvas 2D 렌더러를 직접 작성했다(D037). 정수 배율 제어·번들 크기·가림 처리를 단순하게 맞추기 위해서다. 빌드 JS는 gzip 약 45KB.
- 도메인/애플리케이션 경계는 유지: 진행 상태는 `Game`(application)만 바꾸고 렌더러와 DOM은 읽기만 한다.
- 저장은 localStorage 현재 슬롯 + 자동 백업 2개, 손상 원본 별도 보관, 파일 내보내기/불러오기. 이전 개발 서버의 IndexedDB 저장(schema3)은 다른 주소라 이어지지 않는다.

## 실제 검증 (2026-10-10, macOS arm64, Chromium headless)

- 타입 검사·프로덕션 빌드·배포 경계 검사 통과.
- Vitest 42개: 모든 방의 스폰/문 도착점/문 도달 경로, 모든 대상 접근 가능성, 큰길은 횡단보도로만 통과, 유로프라자→카페 경로, 벽 미끄러짐, 저장 왕복·버전 거부·손상 복구, 카페 첫 커피 1회·잔액·중복 명령.
- Playwright 2개: 새 기자 생성→편집장 대화→엘리베이터→로비→논현로→비투비씨→첫 커피 주문까지 실제 경로 이동, 390×844 터치 화면의 HUD 버튼 크기와 메뉴 열고 닫기.
- 화면 확인은 자동 캡처를 색상 지도로 바꿔 구조(건물·창·간판·도로·인물 배치)를 점검한 수준이다. **사람의 눈으로 본 미감 승인은 아직이다.**

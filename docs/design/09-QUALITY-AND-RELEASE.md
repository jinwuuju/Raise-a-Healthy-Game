# 검증·플레이테스트·출시 기준

## 검증 수준을 구분한다

문서 일관성 검사 ≠ 게임 테스트 ≠ 의학 검수 ≠ 학습 효과 연구. 각 결과에는 대상 버전·방법·기기·범위·남은 제한을 기록한다. 설계 단계에서는 문서·설계 데이터 검사만 있었고, P1에서 [기반 코드/브라우저 검사](../production/P1-FOUNDATION-REPORT.md)를 추가했다. 실제 Q001·의학 검수·학습 효과는 아직 검증되지 않았다.

## 단위·통합·E2E 설계

단위: XP 경계, 보상 멱등성, 조건 판정, 숙련도 증거, 기사 rubric, 구매 잔액, prerequisite 그래프.
통합: 명령→저장→projection, 보상 중 저장 실패, 동일 명령 재처리, 콘텐츠 로드 실패, 이전 버전 저장 이행.
E2E: 새 게임→Q001→기사→재실행, Q010 승진, HTML 모달 중 이동 금지, 키보드만으로 퍼즐, export/import 복구.

중요 경계: 0XP·99레벨, 초과 XP, 이미 받은 보상, 조건 미충족 발행, 음수/소수 재화 입력, 미검수 콘텐츠, 존재하지 않는 asset, 손상 save, 최신 save를 구버전 로드, 동시에 열린 두 탭, 장면 전환 중 새로고침, IndexedDB 사용 불가, 브라우저 저장 용량 부족.

스냅샷 UI 테스트를 수백 개 만드는 대신 기능 계약과 실제 플레이 경로를 우선한다. 수치표가 바뀌면 파생 표를 재생성하고 경계 검사를 돌린다.

## 첫 10분 플레이테스트

내부 종이 검토 2회 후 대상 독자 5명 정도의 형성 평가를 목표로 한다. 정답을 알려주거나 의도를 설명하지 않고 시작 위치만 제공한다. 질문은 종료 후 “어떤 일이 있었나”, “왜 그 경로를 연결했나”, “다음에 무엇을 해보고 싶나”. 소표본 비율을 일반 인구의 학습 효과로 해석하지 않는다.

첫 목표: 5명 중 4명 이상이 진행자 개입 없이 첫 기사 완료, 캐릭터 선택 포함 중앙값 9~13분, 외형 선택 후 이동 시작 30초 내, 대부분이 다음 행동을 말할 수 있음. 2명 이상이 같은 곳에서 60초 넘게 이유 없이 헤매면 그 구간을 수정한다. 시간보다 의미 있는 발견이 있었는지 우선한다.

학습 전이 검토는 플레이와 별도 동의하에 새로운 배치의 짧은 과제로 본다. 힌트 수준과 접근성 모드를 기록한다. 3~7일 뒤 기억 확인은 선택이며 기능 출시의 필수 대규모 실험으로 만들지 않는다. 목표 달성 전에는 ‘학습 효과 입증’이라는 표현을 쓰지 않는다.

## 성능 예산: 검증 전 목표

PC 기준 기기는 P1에서 CPU/GPU/OS/브라우저/해상도를 명시한다. 브라우저는 출시 시점의 Chrome·Edge·Firefox·Safari 최신 안정판에서 실제 지원 범위를 확정한다. 현재 전부 호환된다고 보증하지 않는다.

목표: 대표 탐험 60fps, 프레임 시간 p95 20ms 이하, 저성능 모드 30fps 이상. 셸+첫 지역 압축 전송 8MB 이하, 후속 지역 묶음 각 5MB 이하. 10Mbps·RTT 100ms 조건의 냉시작 첫 이동 10초 이하. 캐시된 장면 전환 1초 이내, 저장 동작으로 눈에 띄는 입력 정지 없음. 30분 왕복 후 메모리가 계속 증가하지 않음. 목표 미달이면 자산·장면 정리를 우선하고 의학 내용을 삭제해 숨기지 않는다.

## 출시 차단 기준

P0 심각도: 진척 유실·중복 보상으로 상태 손상·시작/완주 불가·중대한 의학 오류.
P1 심각도: 필수 경로 막힘·키보드 필수 동작 불가·잘못된 해금·검수/권리 누락.
P2 심각도: 선택 기능 오작동·일부 레이아웃·경미한 성능 저하.

1.0은 미해결 P0/P1 0개, 필수 경로 전체 확인, 모든 배포 의학 콘텐츠 승인, 저장 이행·복구 성공을 요구한다. P2는 영향·회피법·수정 계획을 공개하고 출시 판단한다. 릴리스 버전/단계 P0와 결함 심각도 P0는 기록에서 각각 stage/severity로 명시한다.

## 출시·롤백

staging에서 빌드 manifest와 해시를 고정→전체 스모크→기존 저장 이행→배포→새 게임·기존 저장 스모크→문제 시 이전 정적 빌드 복원. 이전 빌드가 새로운 저장을 읽을 수 없으면 무조건 덮어쓰지 않고 백업 복원 또는 호환 패치를 택한다. 콘텐츠 비활성화는 미완료 퀘스트를 복구 경로로 보내며 이미 얻은 기사를 지우지 않는다.

검증 기록은 [단계 완료 양식](../templates/STAGE-REPORT.md)에 남긴다. 수행하지 않은 항목은 미측정/미검증으로 명확히 쓴다.

# 질환 아카데미: 기관마다 함께 구현하는 질환 취재 (D071)

> **D108(2026-10-19) 변경:** 표의 ‘입문 질환’은 기본(일반인 수준), ‘심화 질환’은 그 장기 기본 졸업 뒤 여는 심화이며, ‘Lv.61 이후·P7’ 배치는 쓰지 않는다. 이 문서와 다르면 [설계 19 기본·심화](19-BASIC-AND-ADVANCED.md)가 우선한다.

상태: D074/Q003의 판막질환 기초 초안·같은 공간의 정상/협착/역류 비교·6단계 취재·기사까지 구현했다. 공개 질환 도감은 없으며, 미검수 본문은 Q003 취재 안에서만 검수 전 모형으로 표시한다. 다른 질환과 허브의 배치는 아직 기획 가설이다. [실제 동반 범위·검증](../production/Q003-VALVE-REPORT.md).

## 1. 왜 세 번째 핵심 축인가

건강기자는 몸의 정상 구조를 아는 데서 끝나지 않고, 질환이 왜 생기고 어떻게 나타나며 어떻게 확인·치료·예방하는지, 그리고 그 정보를 독자에게 정확히 전하는 법을 알아야 한다. 그래서 게임의 핵심 축을 셋으로 둔다.

1. **인체 탐험**: 정상 구조와 작동 원리를 직접 걸으며 관찰한다(현재 심장 구현).
2. **질환 취재**: 같은 공간에서 질환 상태를 비교하고 원인·검사·치료·예방의 근거를 모은다(이 문서).
3. **기사 작성**: 모은 근거로 독자의 질문에 답하고 오해를 바로잡는다(기자 아카데미, 13번 문서).

설명문을 읽고 퀴즈를 푸는 방식이 아니라 **직접 비교하고 자료를 해석해 원리를 알아내는 취재**로 만든다. 가상 환자의 진단을 맞히거나 치료를 처방하는 게임이 아니다.

## 2. 동반 구현 규칙 (가장 중요)

질환을 한 번에 몰아서 개발하지 않는다. **각 기관·허브를 구현하는 작업 단위에 그 기관의 질환 모듈을 함께 넣는다.**

| 기관 작업 | 같은 작업 단위에 반드시 포함 |
|---|---|
| 허브 입문(정상 탐험) 구현 | 4절 표의 입문 질환 1~2개: 질환 레이어 설계, 기초 카드 초안(draft), 연결될 퀘스트 자리 |
| 허브 입문 퀘스트 구현 | 정상 관찰을 먼저 완료한 뒤 열리는 입문 질환 취재 1개 이상 |
| 허브 심화 구현 | 4절 표의 심화 질환 모듈 |
| 이미 구현된 기관에 새 취재 추가 | 그 공간에 맞는 질환 레이어가 있는지 검토하고 BACKLOG에 기록 |

- 순서는 항상 **정상 → 질환**이다. 정상 기능을 관찰하지 않은 상태에서 질환을 먼저 가르치지 않는다.
- 합병증·관련 기관이 아직 구현되지 않았으면 인체 지도처럼 ‘준비 중’ 연결로 표시하고, 빈 내용을 의학 사실로 채우지 않는다.
- 기관 작업의 완료 기록(STATUS)에 ‘포함한 질환 모듈 / 미룬 질환 모듈과 이유’를 함께 적는다.

## 3. 질환 취재의 기본 흐름 (6단계)

| 단계 | 플레이 | 결과물 |
|---|---|---|
| 1. 정상 기준 | 이미 탐험한 정상 공간의 관찰을 다시 확인 | 정상 관찰 카드(재사용) |
| 2. 질환 레이어 비교 | 바디스코프로 같은 공간을 질환 상태로 전환해 무엇이 달라졌는지 2~3개 관찰 | 정상↔질환 비교 카드 |
| 3. 원인·위험 요인 | 바꿀 수 있는 것/없는 것, 개인/환경·사회 요인으로 분류 | 위험 요인 지도 |
| 4. 검사·자료 해석 | 측정 조건·반복 측정·검사가 알려 주는 것과 못 하는 것 비교(가상 데이터 라벨) | 자료 해석 메모 |
| 5. 치료·관리 원리 | 전문가 인터뷰 NPC, 생활 관리와 약 계열의 작용 원리, 합병증으로 이어지는 다른 기관 문 | 인터뷰 노트·연결 기관 |
| 6. 기사·팩트체크 | 흔한 오해 하나를 바로잡는 설명기사나 팩트체크 발행 | 기사·독자 반응 |

- **질환 레이어**: 새 맵을 만들지 않고 정상 공간 위에 상태를 바꿔 보여 준다. 예: 판막이 덜 열림(협착)·닫혀도 새는 흐름(역류), 전도 신호가 불규칙하게 퍼짐(심방세동), 관상동맥이 좁아져 흐름이 줄어듦, 기도가 좁아지고 점액이 늘어남(천식), 사구체 여과막에서 단백질이 새어 나옴(만성콩팥병). 레이어도 ‘검수 전 모형’과 단순화 한계를 표시한다.
- 입문 모듈 최소 단위: 기초 카드 + 질환 레이어 1개 + 오해 팩트체크 1개 + 기사 1개. 심화 모듈은 연구 해설·수치와 위험 전달·합병증 연결을 더한다.
- 13번 기자 아카데미의 실습(출처 검증·연구 읽기·수치·인과·윤리·환자 이야기)을 질환 취재 안에서 경험하게 한다.

## 5. 레벨 구간 요약

| 구간 | 질환 취재의 깊이 | 주요 예시 |
|---|---|---|
| Lv.1~10 | 측정과 관찰의 조건, 정상과 질환 상태 비교 | 고혈압·동맥경화 기초, 판막질환·부정맥 레이어 |
| Lv.11~20 | 감염과 만성 염증 구분 | 천식, 폐렴, 감기와 인플루엔자 |
| Lv.21~30 | 생활과 대사가 얽힌 질환, 흔한 오해 검증 | 당뇨병, 지방간질환, 위식도역류질환, 충치·치주질환 |
| Lv.31~40 | 원인 질환과 결과 장기 손상 연결 | 만성콩팥병, 요로감염 |
| Lv.41~50 | 신호·감각·움직임의 질환, 응급과 만성 구분 | 뇌졸중, 치매, 백내장·녹내장, 관절염 |
| Lv.51~60 | 면역 과반응·자가면역, 생애주기 | 아토피피부염, 알레르기, 자가면역질환, 생식 건강 |
| Lv.61~80 | 중증·만성 질환과 다질환 관리, 연구 근거 | 심근경색, 심부전, 암, 다질환 |
| Lv.81~99 | 복합 질환, 증상만으로 단정할 수 없는 이유를 자료로 해설, 임상연구·치료 근거와 한계 분석 | 고난도 종합 취재 |

Lv.81~99의 ‘감별’은 플레이어가 진단을 맞히는 것이 아니라, 같은 증상이 여러 원인에서 나올 수 있음을 자료로 보여 주고 기사에서 단정하지 않는 법을 익히는 것이다.

## 6. 질환 도감과 접근

- 질환 도감은 [전신 아틀라스](12-WHOLE-BODY-ATLAS.md) 검색의 ‘질환’ 축이다. 질환은 신체 맵과 별도 질환 ID를 가지며 관련 기관·계통·개념으로 서로 연결한다.
- 카드 4층(10초 요약·1분 설명·5분 심화·근거 서랍)과 내용 순서: 정의 → 원인·위험 요인 → 병태생리 → 증상 → 검사·진단의 의미 → 치료 원리 → 예방·관리 → 합병증(다른 기관 링크) → 흔한 오해 → 단순화 한계 → 출처.
- 기초 정보는 검수된 범위에서 레벨과 무관하게 검색할 수 있고, 심화 취재만 단계적으로 열린다. **미검수 초안은 도감 카드로 공개하지 않고**, 퀘스트 안에서만 ‘검수 전 모형’과 함께 보인다.
- 수첩(D067) 단일 소유: 질환 레이어 관찰은 ‘인체 탐험’ 탭의 해당 기관 아래 ‘질환 비교’ 토글, 질환 취재 근거는 ‘취재 파일’, 질환 기사는 ‘발행 기사’에 둔다. 다른 곳은 바로가기만.
- 오늘의 점심(D068) 카드의 영양 수치에서 관련 질환 기초 카드로 가는 ‘더 알아보기’ 링크는 허용한다. 메뉴나 개인의 위험을 판정하지 않는다.

## 7. 질환 데이터 계약

- 커버리지 장부: data/catalog/diseases.v0.1.json(만들 때 tools/check_design.py 검사 추가). 행마다 id(disease. 접두사), 이름(일상어·의학 용어·영문·약어), 관점 태그(감염·종양·대사·염증·자가면역·유전·손상·퇴행·정신건강·노화), primaryHubId, anatomyIds, relatedSystemIds, 선수 개념, 입문/심화 구분, 레벨 구간, status(planned), review(null).
- 본문: data/content/diseases/질환id.v0.x.json, 07번 문서의 상태 단계(draft → source_checked → medical_reviewed …)와 Source·Review 계약을 그대로 따른다.
- 검사 규칙(구현 시): 허브·해부 id 실재, 허브마다 입문 질환 2개 이상 배정, 입문 질환은 같은 허브의 정상 개념을 선수 개념으로 가짐, review를 지어내지 않음, 미검수 본문이 도감 공개 목록에 없음.

## 8. 안전·정확성 규칙

- 증상을 입력받아 진단하거나, 개인별 위험 확률·치료·약을 추천하지 않는다. 약은 계열과 작용 원리만 다루고 제품명·용량·복용법을 쓰지 않는다.
- 진단 기준 수치(혈압·혈당 기준 등)는 국내 학회·기관 지침의 판본·날짜·지역을 붙인 갱신 가능한 카드로 만들고 영구 정답으로 고정하지 않는다.
- 응급 증상 행동 안내(예: 뇌졸중·흉통)는 별도 임상 출처와 검수가 있을 때만 넣는다.
- 가상 환자 사례는 명확히 가상이라고 표시하고 실제 환자 정보를 쓰지 않는다. 환자는 존중받는 취재 대상이며 벌점·구경거리가 아니다.
- 낙인 금지: 비만·흡연·음주·정신건강·감염병·생식 건강을 개인의 도덕적 실패로 그리지 않고 생물·심리·사회 요인을 함께 다룬다. 정신건강을 뇌의 고장 퍼즐로 단순화하지 않는다. 자살·자해가 관련되면 보도 권고 기준과 도움 연락처 규칙을 따로 정한 뒤에만 다룬다.
- 유병률·생존율 등 수치는 출처·연도·대상과 분모를 붙인다. 상관을 인과로, 연구 단계(세포·동물·사람)를 넘어 일반화하지 않는다.
- 질환 선정 기준: 한국에서 흔하거나 부담이 큼(공식 통계로 확인 후 기록), 중증도, 예방·관리 가능성, 오해 빈도, 기사 수요, 다른 기관과의 연결성.

## 9. 개발 단계 배치

| 단계 | 질환 작업 |
|---|---|
| P3(현재 심장) | Q008 고혈압·동맥경화 기초, Q002~ 심장 취재와 함께 판막질환·부정맥·협심증 레이어 설계 (구현: Q003 판막질환, Q005 부정맥 첫 모듈 심방세동 · D077) |
| P4 | 질환 도감 데이터 장부·검증기, 질환 레이어 공용 규칙(콘텐츠 검증기와 함께) |
| P5 | 호흡·소화·대사·입 허브 입문 질환(천식·폐렴·위식도역류·당뇨병·충치 등) |
| P6 | 나머지 허브 입문 질환, 복합 연결(고혈압·당뇨병 → 콩팥·눈·뇌) |
| P7 | 심화 질환(심근경색·심부전·암·다질환), 연구 근거 해석, 고난도 종합 |

예산 가설: 1.0까지 허브당 입문 2~3개·심화 1~3개의 질환 모듈(약 36~60개). 나머지는 기초 카드로 시작한다. 실제 수량은 제작 속도와 검수 역량으로 다시 정한다.
